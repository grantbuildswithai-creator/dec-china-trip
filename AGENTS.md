## Hard rules

- **This repo is PUBLIC.** Never commit confirmation numbers, booking references, passport numbers/details, payment info, or ticket PDFs/images — in any file, commit, or branch. Plan-level facts only (cities, dates, times of travel already in the README). Sensitive details go to the Drive folder only.
- **WhatsApp is a relay, not a channel Muse can use.** Sherly sends things to Grant on WhatsApp; Grant forwards them into the chat; Muse drafts replies/documents and Grant sends them back himself. Never claim a message was sent to Sherly.
- **Don't invent bookings.** A slot stays blank / "not yet recorded" until Grant or Sherly supplies the real detail. No guessed flight numbers, hotel names, or confirmation codes.
- **Verify dates.** Check weekday/date arithmetic with a tool before writing a date into the plan.

## Update protocol

When Grant drops new material into the chat (a confirmation, a change from Sherly, a decision):

1. Extract the facts; flag anything that conflicts with the README rather than silently overwriting.
2. Update `README.md` (status, day plan, open items) and this file's open threads if they change.
3. Commit with a clear message and read the files back on GitHub to verify the push landed.
4. Tell Grant what changed, briefly. If a reply to Sherly is needed, draft it ready to paste.
